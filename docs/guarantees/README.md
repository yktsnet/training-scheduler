# Guarantee Ledger

このリポが外へ約束している振る舞いと、それを守るテストの一覧である。約束が破れればテストが落ちるので、
ここに書いたことは気づかないうちに実装とずれていかない。**ここに載っていない振る舞いは約束ではなく、予告なく変わりうる**。
対象は `backend/` が `/api` 配下に公開する HTTP エンドポイントで、ステータスコード・レスポンスの中身・DB に残る結果として外から観測できる振る舞いを約束とする。frontend の画面、管理者トークンの作り方などハンドラ内部の実装、静的ファイルの配信は対象外である。この台帳は設計文書と同じ扱いで、実装と食い違えば指摘の対象になる。

- 目的: いま何を約束しているかを1か所で読む。変更の前に、変えてはいけない約束をここから引く。テストの無い約束を Gaps に残す
- 分け方: 約束の対象（API のリソース）ごとに1ファイル。テストファイルや Issue の単位では分けない。新しいリソースを作ったときだけファイルを足す
- 書き方: 各ファイルに「保証｜対応テスト」の表を1つ置き、1行に約束を1つ、宣言文で書く。「A し、B する」と書きたくなったら行を分ける。主語（エンドポイント）は行ごとに書く。出典・経緯・設計の理由は書かない。画面の見た目、手で確かめる操作、frontend のビルド検査は載せない。約束が10行以上のファイルは、何についての約束かで `##` の見出しを立て、見出しごとに3行以上の表を置く。見出しは行の主語になる名詞句にし、10行未満のファイルには置かない。ファイルは分けない
- 引き方: Issue で「維持する保証」を挙げるときは、変更の対象のファイルを開いて約束を引く。テストが落ちたら、テストの関数名で台帳を検索すると、破れた約束の行が見つかる。約束が守られていることは、全テストを流す `make test` と CI が確かめる。コードのファイルから約束を引く仕組みは置かない（実装とテストの名前は1対1でなく、機械では正確に引けない）
- 運用: 変更の前にこの README を読み、変更が触れるファイルから「維持する保証」を引く。約束を足す・変える・消すときは、承認を受けた保証節の文のまま、該当するファイルの表に行を足す・直す・消し、対応テストも同じ変更で直す。Issue や作業ごとにファイルや節を起こさない。テストの無い約束は Gaps に書き、テストを足したら表へ移す。台帳とテストのずれは `guarantee-audit` で棚卸しする
